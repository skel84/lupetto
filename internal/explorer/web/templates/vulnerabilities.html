{{template "icon" "info"}}How these counts are made. Both images are scanned the same way with Grype’s default settings.What this meansHide
  • Unique issues. A finding’s ID and its related IDs (for example a GHSA and its CVE) count as one issue, once per image however many packages it affects. Each finding has Grype’s severity (its own record’s, or a related record’s when its own is unknown, so a distribution’s triage such as Debian’s “negligible” is kept), and an issue takes the highest of its findings.
  • The same images you would run. Lupetto’s side is the track’s newest published image; upstream is the image named in the products file. Both are scanned for this Explorer’s architecture, and upstream tags are resolved to a digest at scan time.
  • Fixed and unfixed. Unlike the security-feed counts elsewhere in the Explorer, these include issues with no fix yet. “Fixed in” comes from the advisory data, which can name a version the Wolfi index doesn’t have, for example when a version stream’s later builds aren’t published there; “Latest in Wolfi” on Images is what a rebuild can use.
  • Same database. Counts are only comparable when both scans used the same database build; differing builds are flagged.
  • Stale or failed. A failed scan keeps the previous result and marks it stale; a result also goes stale when the newest image changes or it is older than twice the scan interval. A failed or missing scan is never shown as zero.
