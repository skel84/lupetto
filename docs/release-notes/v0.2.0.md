# Lupetto v0.2.0 release notes

v0.2.0 lets Lupetto images stand in for upstream images in charts that pass only `args`. Each image still holds one selected Wolfi package and its dependency closure. Two explicit, recorded options are added: an entrypoint and a CA certificate bundle. The [changelog](../../CHANGELOG.md#v020-2026-10-22) lists every change.

## Highlights

### Entrypoint for args-only charts

Kubernetes treats `args` as the command when an image has no `ENTRYPOINT`. That is why `docker run <lupetto-image> --help` failed with `exec: "--help": executable file not found`. Set the entrypoint per product:

```yaml
version: 1
products:
  - package: kyverno
    selectors: ["1"]
    entrypoint: [/usr/bin/kyverno]
```

or per build:

```bash
lupetto build kyverno 1 --entrypoint /usr/bin/kyverno
lupetto build memcached 1 --entrypoint /usr/bin/memcached --entrypoint=-u --entrypoint memcached
```

The build checks that the executable exists in the image (following its `/bin` → `usr/bin` style symlinks) and is executable. Package binaries are not always named after the package; `kubectl-1.34`, for example, installs `/usr/bin/kubectl-1.34`. Check a wrong path first with `lupetto build … --no-load`, which fails with `… /usr/bin/kubectl does not exist`.

### CA bundle for packages without TLS roots

Packages such as `external-dns-0.21` and `kubectl-1.34` do not depend on a CA bundle, so their TLS clients fail with `x509: certificate signed by unknown authority`. Add one with `caBundle: true` in the product or `--ca-bundle` on the build. apko's retained lock and the validated SPDX record the exact `ca-certificates-bundle` version installed.

### `busybox 1` builds again

A request for an APK by its own name no longer fails as ambiguous because other packages provide that name at the same version.

## Upgrading from v0.1.0

- **No action is needed for existing tracks.** Without the new options, apko receives the same configuration as in v0.1.0, and annotations and records are unchanged. `status` keeps reporting existing images as before.
- **Adding an option to a product** makes its tracks `config-changed`. With `status --exit-code` that exits 3, the existing rebuild signal. Rebuild with the CLI, or use Explorer's Rebuild button, to apply it. Removing the option has the same effect.
- **Status consumers** should accept the new `config-changed` state and the optional track fields `entrypoint` and `caBundle`; the document version stays 2. Run v0.2.0 Explorer with a v0.2.0 CLI. The v0.1.0 Explorer shows `config-changed` as "Unable to compare", and it cannot pass the options to builds.
- **Explorer builds** now read the products file before starting. If it cannot be read, the build is refused with 503 instead of being built without the product's options.
- **Selection:** an exact-name request that used to fail as ambiguous now selects the APK named exactly as requested. Other ambiguous requests still fail.

## Reproducibility

Lupetto has never produced identical digests across separate builds of the same package. Each build records a new creation time, and apko embeds the build workspace's key path in `/etc/apko.json`. For identical inputs apko produces an identical image. The v0.2.0 evidence shows that a build without the new options gives apko byte-identical inputs to v0.1.0, and that apko reproduced v0.1.0's digest from them ([verification](../verification.md#image-entrypoint-v020)).

## Not included

`CMD`, working directory, user, and environment settings; other extra packages; per-selector options; and multi-architecture image indexes.
