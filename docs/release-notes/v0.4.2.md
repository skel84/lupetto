# Lupetto v0.4.2 release notes

v0.4.2 makes `lupetto status` see security fixes in subpackages, so a track whose image carries a vulnerable subpackage becomes `fixes-available` and is rebuilt. Images, build records, the products-file format, and the status document schema are unchanged from v0.4.1. The [changelog](../../CHANGELOG.md#v042-2026-11-09) lists every change.

## Fixed

### Fixes in subpackages were never reported

Wolfi's security feed lists fixes under the source (origin) package: `expat 2.10.0-r0` fixes CVE-2026-113351 and CVE-2026-115506. An image's installed APK database names the subpackage it contains, such as `libexpat1`. v0.4.1 looked the feed up by installed name only, so it never found that fix: `openjdk-25-default-jvm:25` carried `libexpat1 2.9.0-r0` while `2.10.0-r1` was available, its track stayed `current`, and nothing rebuilt it. The same gap applies to every subpackage, for example `libssl3` and `libcrypto3` from `openssl`.

`status` now reads each installed package's origin (`o:` in the APK database) and checks the feed under both the installed name and the origin. A missing fix still names the installed package (`libexpat1`) in `missingFixes`. Feed entries that cannot be evaluated (an unorderable fixed version or no recognised advisory ID) are attached to a track through the origin too.

## Upgrading from v0.4.1

Replace the CLI, or the combined container. The installed-package cache moves to version 2: entries written by v0.4.1 lack origins, so v0.4.2 treats them as misses and reads each image's installed database again once, so the first `status` run after the upgrade downloads each newest image's installed database again.

Expect the first run after the upgrade to report more tracks as `fixes-available` than before, and so to rebuild more images.
