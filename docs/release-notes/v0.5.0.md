# Lupetto v0.5.0 release notes

v0.5.0 lets a product install several Wolfi packages in one image and run it as a numeric non-root user. Products files, images, and build records from v0.4.2 stay valid and unchanged when the new options are not used; the record stays version 6 and the status document version 2. The [changelog](../../CHANGELOG.md#v050-2026-11-19) lists every change.

## Added

### Additional packages

An image used to hold one selected APK and its dependency closure, so a PostgreSQL server could not carry its contrib extensions, and a PHP base could not carry its web server. A product's optional `packages` list, or the repeatable `--package` flag on `build` and `sbom`, adds further top-level APKs:

```yaml
version: 1
products:
  - package: postgresql-18
    selectors: ["18"]
    packages: [postgresql-18-contrib, busybox]
    user: "26"
```

Each additional package resolves in the same verified APKINDEX as the selected APK, to its highest version for the architecture, and is pinned exactly. The build fails without fallback when one is unavailable, resolves to an APK already selected, or differs in the apko lock or the image. The validated SPDX document and its attestation cover every installed APK as before. The selected APK still names the image and its tag.

`status` reports a changed list as `config-changed` (`configChanges: ["packages"]`, order ignored). A newer additional package alone does not make a track `update-available`; a security fix for it, matched by name and origin as in v0.4.2, makes it `fixes-available`.

### Image user

Lupetto images ran as root, so charts that set `runAsNonRoot` without `runAsUser` could not use them. A product's optional `user` (`"uid"` or `"uid:gid"`, non-zero uid), or `--user`, sets the image config `User` to the explicit `uid:gid` and adds a `nonroot` user and group with those IDs, which programs such as PostgreSQL's `initdb` need. `status` reports a changed user as `config-changed` (`configChanges: ["user"]`).

Both options are recorded in the `lupetto.image.packages` and `lupetto.image.user` annotations and in optional record fields. Explorer passes a tracked product's options to its builds, taken from the entry that tracks the requested selector.

## Upgrading from v0.4.2

Replace the CLI, or the combined container. Nothing is rebuilt until a products file uses the new options; adding them to a product makes its tracks `config-changed` once. An image has no shell unless a package brings one, so programs that run helpers through `/bin/sh`, such as `initdb`, also need a package like `busybox`.
