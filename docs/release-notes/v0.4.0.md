# Lupetto v0.4.0 release notes

v0.4.0 shows how a Lupetto image compares with the upstream image it replaces, by vulnerability count, and lets Prometheus scrape Explorer's state. The `lupetto` CLI builds the same images as v0.3.1. The [changelog](../../CHANGELOG.md#v040-2026-10-23) lists every change.

## Highlights

### Lupetto versus upstream, per track

Name the upstream image next to each selector in the products file:

```yaml
version: 1
products:
  - package: metrics-server
    selectors: ["0"]
    upstream:
      "0": registry.k8s.io/metrics-server/metrics-server:v0.8.0
```

Explorer scans the track's newest published image and the upstream image with the embedded Grype v0.121.0 library and its default settings, for the status architecture. The new **Vulnerabilities** page shows both images' counts of unique issues per severity and the difference. Each track's page lists the issues Lupetto removed, those both images have, and those only Lupetto's image has. Images links each track to it.

A GHSA and its CVE count as one issue, and an issue counts once per image however many packages it affects. A failed scan keeps the previous result and marks it stale; a scan that never succeeded shows no counts. Neither is ever shown as zero. In verification, Explorer's counts matched the `grype` v0.121.0 executable on the same digests ([evidence](../verification.md#upstream-vulnerability-comparison-v040)).

Read "new" issues with care. Fix versions come from advisory data, which can name versions the Wolfi index does not have. In verification, a current `kubectl-1.33` image had 59 issues upstream did not, all from advisories for its origin `kubernetes-1.33` with fixes in 1.33.6–1.33.13, while the index's newest `kubectl-1.33` is 1.33.4-r3. No rebuild can pick those fixes up. "Latest in Wolfi" on Images is what a rebuild can use.

### Prometheus metrics

`GET /metrics` exports each track's state, the last status time, per-severity vulnerability counts for both images, scan time, success, staleness, and database build times. Labels carry no issue IDs or digests. The endpoint answers any Host for GET and HEAD, so Prometheus can scrape a pod address; every other path still needs `--allowed-host`. The [README](../../README.md#upstream-vulnerability-comparison) lists every series.

## Upgrading from v0.3.1

- **Explorer downloads a vulnerability database on first start.** Scanning is on by default. After the first status check, Explorer fetches Grype's database from `grype.anchore.io`: about 195 MB that unpacks to about 3.3 GB. It checks for a newer one before each pass with something to scan, typically daily. To keep v0.3.1 behavior and network use, start Explorer with `--scan-interval 0`. That removes the pages, the Images links, and the vulnerability metrics; track and status metrics remain.
- **Allow the egress.** `grype.anchore.io`; each upstream registry and the hosts it redirects layer downloads to (for example `cdn.registry.k8s.io` for `registry.k8s.io`); and the Lupetto registry. Upstream pulls use the same `DOCKER_CONFIG` as publication, then anonymous access.
- **Size the cache volume for about 7 GB.** An update unpacks the new database beside the old one. Image layers are unpacked under `TMPDIR` during a scan and removed afterwards. In the container, pass `-e TMPDIR=/var/cache/lupetto` to use the cache volume instead of the writable layer.
- **Memory.** Peak resident memory was about 260 MiB scanning two kubectl images and about 330 MiB scanning `postgres:17`, measured on macOS. Set a container memory limit of at least 512 MiB; 1 GiB leaves headroom for larger images, which were not measured. `--scan-max-image-size` (default 2 GiB of compressed layers) bounds the images scanned.
- **Larger binary.** `lupetto-explorer` grows from about 10 MB to about 87 MB stripped, and the combined image should grow by about as much (the container was not rebuilt for these notes). The `lupetto` CLI does not include Grype.
- **Products files.** `upstream` is optional, and files without it are unchanged. The v0.3.1 CLI rejects files that use it ("invalid products fields or types"), so upgrade the CLI and Explorer together. The combined container ships both.

## Not included

Scans of images other than each track's newest, vulnerability history over time, policy gates on the counts, multi-architecture comparisons, and scanning from the `lupetto` CLI.
