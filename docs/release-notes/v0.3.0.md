# Lupetto v0.3.0 release notes

v0.3.0 makes every Lupetto image identifiable to vulnerability scanners. Each image still holds one selected Wolfi package and its dependency closure, plus Wolfi's base layout, which is now always added. The [changelog](../../CHANGELOG.md#v030-unreleased) lists every change.

## Highlights

### No more false-clean scans

Scanners recognize a Wolfi image by `/etc/os-release`, which only the `wolfi-baselayout` APK installs. Packages that do not depend on it, many static Go binaries among them, produced images without it. On such a v0.2.0 `metrics-server` image, Trivy detected no OS and reported nothing at all. Grype still found the Go modules' vulnerabilities but no longer matched the APKs against Wolfi's security feed. After the rebuild, both detect `wolfi 20230201`: Trivy reports 20 vulnerabilities, and Grype reports 59 APK and 35 Go-module matches ([evidence](../verification.md#wolfi-base-layout-v030)).

Every build now adds `wolfi-baselayout`, and fails unless `/etc/os-release` has `ID=wolfi` and a `VERSION_ID`. The version is not pinned in Lupetto: apko's retained lock records it, and the SPDX document is validated against it like any dependency.

### Why a track is `config-changed`

`status` tracks now list what differs in `configChanges`, and the table prints a line such as:

```text
metrics-server 0: newest image configuration differs: baseLayout
```

Explorer shows the same reasons under "Configuration changed", for example "Rebuild changes: adds Wolfi base layout (scanner OS identity)".

## Upgrading from v0.2.0

- **Expect one rebuild wave.** `status` reads the installed APKs of each track's newest image. Images without `wolfi-baselayout` are now `config-changed`, so `status --exit-code` exits 3 until they are rebuilt with v0.3.0. Images whose closure already had it (for example `busybox`) stay `current`.
- **Image contents grow slightly.** The base layout and its dependency `ca-certificates-bundle` add about 146 KB compressed: `/etc/os-release`, `/etc/passwd`, `/etc/group`, `/etc/nsswitch.conf`, system TLS roots, and the `/bin` → `usr/bin` style links. An image that relied on having no `/etc/passwd` or no TLS roots should be checked.
- **`caBundle: true` is still worth setting** where TLS roots are required. It records and checks the requirement instead of relying on the base layout's dependencies.
- **Status consumers** should accept the optional `configChanges` field and show unknown values as a change; the document version stays 2. Run v0.3.0 Explorer with a v0.3.0 CLI to see the reasons.
- **Builds without options** no longer give apko v0.2.0's configuration byte for byte; the extra package line is the only difference. Annotations and records are unchanged.

## Not included

An option to leave the base layout out, pinning its version in the products file, and multi-architecture image indexes.
